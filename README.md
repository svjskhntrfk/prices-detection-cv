# prices-detection-cv

Решение задачи **Lenta Tech Computer Vision Challenge** — автоматическое обнаружение ценников на полках магазинов и распознавание текстовых полей из видео, снятого роботом-сканером.

---

## О задаче

Робот объезжает стеллажи супермаркета и снимает видео. Задача — по этим видео автоматически:

1. **Найти** все ценники в каждом кадре (bbox с координатами).
2. **Распознать** структурированные данные с каждого ценника: название товара, цены, штрихкод, скидку и т.д.
3. **Собрать** результат в CSV с 28 колонками.

Сложность задачи: движущаяся камера, различные углы съёмки, частичные перекрытия ценников, разные форматы и шрифты.

---

## Технологический стек

| Компонент | Технология | Назначение |
|---|---|---|
| Детекция ценников | **YOLOv8m** (fine-tuned) | Обнаружение bbox ценников в кадре |
| OCR | **PaddleOCR** (Chinese+Latin) | Распознавание текста на кропах |
| Трекинг | **Венгерский алгоритм** | Сопоставление ценников между кадрами |
| Декодирование штрихкодов | **pyzbar** | EAN/QR-коды |
| Обработка видео и изображений | **OpenCV** | Извлечение кадров, фильтрация |
| Метрики качества | **scikit-image** | Резкость, экспозиция, геометрия кропов |
| Оркестрация экспериментов | **hypothesis_campaign.py** | Пакетный перебор гипотез |

### §1 — Извлечение кадров

- Видео читается через OpenCV (`cv2.VideoCapture`).
- Применяется адаптивный шаг — плотнее там, где сцена меняется, реже там, где стеллаж статичен.
- Каждый кадр проходит quality-фильтр: отбрасываются смазанные и пересвеченные кадры по метрике Лапласиана.

### §2 — Детекция ценников (YOLOv8m)

- Используется дообученная модель YOLOv8m на датасете ценников Lenta.
- Для каждого кадра получаем набор bbox с confidence-score.
- Применяется NMS (Non-Maximum Suppression) для удаления дублей.

### §3 — Фильтрация и ранжирование кропов

Каждый кроп проходит многоступенчатую оценку качества:

| Метрика | Что проверяет |
|---|---|
| Геометрия | Соотношение сторон, минимальный размер |
| HSV-анализ | Цвет фона ценника (характерные белый/жёлтый/красный) |
| Резкость (Laplacian) | Размытость из-за движения камеры |
| Экспозиция | Пересвет/недоэкспонирование |

Кропы ранжируются по агрегированному score — лучший кроп трека идёт в OCR.

### §4 — Трекинг (Hungarian Algorithm)

- Между соседними кадрами ценники сопоставляются по IoU через венгерский алгоритм.
- Формируются **треки** — цепочки bbox одного ценника через время.
- `track_merge/H1`: треки с большим перекрытием bbox объединяются для устранения дробления.
- Из каждого трека выбирается **лучший кроп** по качественным метрикам §3.

### §5 — OCR (PaddleOCR)

- Локальный движок PaddleOCR с поддержкой латиницы и кириллицы.
- Запускается на топ-кропе каждого трека.
- Возвращает список `(текст, confidence)` для каждой найденной строки.
- Конфигурация `ocr/H4` — оптимальный баланс скорость/качество по результатам экспериментов.

### §6 — Парсинг полей

После OCR сырой текст разбирается по структуре ценника:

- **product_name** — название товара, из верхней части ценника.
- **price_default** — основная цена (без скидки).
- **price_card** — цена по карте лояльности.
- **price_discount** — цена со скидкой.
- **discount_amount** — размер скидки (руб. или %).
- **barcode** — штрихкод EAN-13/EAN-8, декодируется через `pyzbar`.
- **id_sku**, **code** — внутренние идентификаторы.
- **QR-поля** — `qr_code_barcode`, `price1_qr`…`price4_qr`, оптовые цены.

Конфигурация `parsers/H2+H4` — два комплементарных парсера, обрабатывающих разные форматы ценников.

### §7 — Сборка CSV

- Все треки объединяются в итоговый DataFrame.
- Дублирующиеся треки (тот же ценник с разных кадров) дедуплицируются.
- Сохраняется CSV с 28 колонками (см. раздел «Формат выходных данных»).

## Гипотезно-модульная оптимизация

Каждый блок пайплайна параметризован набором **гипотез** (H1, H2, …):

```
data_input:   H1, H2, ...    ← источник и нарезка видео
preprocess:   H1, H2, ...    ← предобработка кропов
ocr:          H1, H2, H3, H4 ← конфиг PaddleOCR
parsers:      H1, H2, H3, H4 ← парсеры текста
qr_barcode:   H1, H2         ← стратегия декодирования штрихкодов
track_merge:  H1, H2         ← агрессивность слияния треков
```

Оркестратор `final/hypothesis_campaign.py` автоматически прогоняет заданные комбинации на фиксированной выборке (`sample=96`) и сохраняет метрики каждого run-а.

Выбор чемпиона — по метрике **`case_proxy_v2`** (см. раздел «Метрика оценки»), поскольку разметка GT для финального теста отсутствовала.

**Champion-конфигурация:**
```
data_input/H2 · preprocess/H1 · ocr/H4 · parsers/H2 · parsers/H4 · qr_barcode/H1 · track_merge/H1
```

## Метрика оценки

Скрипт `evaluate_matching.py` сравнивает предсказания с ground truth в два прохода.

### Pass 1 — матчинг по штрихкоду

Если штрихкод из предсказания точно совпадает со штрихкодом в GT (после нормализации) — это однозначный матч с `match_score = 1.0`.

### Pass 2 — пространственно-временной матчинг

Для оставшихся строк ищется лучший GT-кандидат по трём критериям одновременно:
- `filename` совпадает,
- `|Δt| ≤ 500 мс` (временная метка),
- `IoU ≥ 0.3` (перекрытие bbox).

Итоговый score матча: `IoU − 0.1 × (|Δt| / 500)`.

### Основные метрики

| Метрика | Описание |
|---|---|
| `final_score` | Доля GT-ценников, у которых нашёлся матч **И** ≥ 80% полей верны |
| `weighted_final_score` | То же, но поля взвешены (barcode = 3.0, price = 2.0, name = 1.0) |
| `case_proxy_v2` | Прокси-метрика для ранжирования без GT (использовалась в данном проекте) |
| `recall` / `precision` / `f1` | Для режима `--detection-only` (только bbox) |

### Запуск оценки

```bash
# Установить зависимости
pip install pandas

# Полная оценка (детекция + OCR)
python evaluate_matching.py \
  --pred outputs/result.csv \
  --gt 26_12-20.csv \
  --out outputs/report.json \
  --matches-out outputs/matches.csv

# Только детекция (bbox + timestamp)
python evaluate_matching.py \
  --pred outputs/result.csv \
  --gt 26_12-20.csv \
  --out outputs/report_det.json \
  --detection-only
```

## Ручная верификация

1. Открыть [final/04_result_best.csv](final/04_result_best.csv), выбрать 10–15 случайных `filename` (`track_XXXXX`).
2. Для каждого трека найти кроп в `outputs/top_crops/track_XXXXX/`.
3. Сверить руками поля `product_name`, `price_default`, `price_discount`, `barcode`.
4. Убедиться, что в большинстве кейсов критичные поля заполнены корректно.
